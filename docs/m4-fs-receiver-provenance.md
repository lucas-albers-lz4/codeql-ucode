# Bounded source-declared receiver provenance

`ql/src/m4/FsReceiverProvenance.ql` is an additive table with columns **call, receiver, declarator, initializer, method, factory**. Its rows join a direct non-optional `read` or `close` member call, through the existing lexical variable relation, to a direct `popen(...)` declarator initializer accepted by the existing source-declared `fs` import guard. The call and declaration must share the same nearest function. The guard rejects recognized receiver writes and recognized variable accesses outside its same-function allowlist of direct member calls and direct `if` conditions.

These are syntactic source observations, not runtime targets or resource identities. `popen` may fail; imports, reflection and runtime state may differ; the existing lexical binder and use inventory do not establish complete language semantics or all possible escapes. Nonmatches are inconclusive, not safe or unreachable. No library dispatch, `getIdentifier`, taint, flow, `path_found`, production query or extractor/schema is changed. The table does not complete #48 or provide #49/#50 modeling.

`bash scripts/m4-receiver-provenance-smoke.sh` creates a fresh isolated database, retains its pre-finalization routing receipt and checks the exact successful-file identities plus zero extraction errors before comparing all four entity spans and scalar fields against the test oracle, with multiplicity. It includes the pinned `luci` fixture and local/formal shadows, unrelated objects, import variants, reassignment, aliases, argument and shorthand escapes, member writes, capture and separate optional-member, optional-call, subscript and parenthesized-callee controls. A real member-call inventory makes each file's control nonvacuous. Separate real query faults weaken lexical identity and receiver-use checks and must expose designated shadow and escape sites to the unchanged full-witness oracle. Each optional-chain guard is also removed separately in a real query, which must add exactly its independently specified full witness and fail the unchanged oracle. The same-count wrong-file substitution uses an existing, out-of-set source file, and per-witness substitutions test the verifier; a separately compiled real query retargets both declaration and initializer of the selected opkg calls to the apk sibling while retaining the call identities and row count. Python guard logic uses explicit exceptions and can also be run under optimization: `python3 -O -B scripts/receiver-provenance-smoke.py` after installing the packs.

The standalone script uses the extractor pack supplied at `extractor-pack`; its source-to-binary provenance is outside this test. The initializer's existing source-declared `fs` guard excludes files with extraction errors, but callers must enforce their own exact extraction-diagnostics gate to establish selection completeness and reject errors before semantics. The fixture oracle is specific to these source bytes, not an independent enumeration of arbitrary codebases. Its original selected-case witnesses were source-derived; additional production rows in the unfiltered table were reviewed against source after the first query run, not enumerated independently before it. See the existing source-declared fs documentation for the conservative import guard's scope.
