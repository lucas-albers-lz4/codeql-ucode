# Source-declared unary `stat` model and DDNS observation

The `SourceDeclaredFsStatCall` model identifies a direct unaliased source-declared `fs.stat` call with exactly one raw expression argument; spread arguments and other arities are excluded. `getPathArgument()` returns that raw argument node. The attribution applies only to source syntax and conservative competing-binding exclusions. It establishes no imported lexical or runtime callee binding, path flow, sink, sanitizer, authorization or security conclusion. Interpret unsupported forms and nonmatches as inconclusive. Production taint, Concepts and default suites are unchanged.

The [source-first model oracle](../ql/test/issue155-stat-observation/model-manifest.json) specifies eight real DDNS calls at lines 96, 118, 204, 208, 254, 311 and twice on 312, and exact argument spans and kinds. Fixed paths and request-shadow syntax are positive model controls; they are not evidence of request flow.

The testing-only inventory records one narrow source shape for [#155](https://github.com/lucas-albers-lz4/codeql-ucode/issues/155): a direct, non-optional, unary `stat` call with a template argument containing `request.args.service_name`, in the selected DDNS handler. It attributes the spelling to an earlier, unaliased `fs` named import only after rejecting competing same-name imports, bindings and writes in the file. The receiver read is associated with the selected handler formal using the variable API. The output identifies the call, import, handler and argument components; it is not an fs sink, data-flow edge, runtime target or security finding. Interpret unsupported and unresolved cases, including nonmatches, as inconclusive; the table emits no status or `path_found`.

The selected real source is LuCI commit `b2e0be4b46ec0fd43394c081fa7c50657af14011`, `applications/luci-app-ddns/root/usr/share/rpcd/ucode/ddns.uc`, blob `32d1da738b4932159a39bcda7ee6c72b5c58a8fd`, SHA-256 `924bd2b53fbc64d2a00a479e36ef3c9239488445fc1ced70122e8ac3735fdc2b`. Line 96 contains ``stat(`${logdir}/${request.args.service_name}.log`)``. The query expects that source staged at `usr/share/rpcd/ucode/ddns.uc`; the original source path is not evidence of installation.

The two-file duplicate-import control is kept in its own staging root. The [retained observation and mutation evidence](https://github.com/lucas-albers-lz4/codeql-ucode-ledger/tree/b0d9b08c75f783cb49f780344a17172ba5604961/evidence/application-source-observations-20261124) reports one real and two synthetic baseline rows, and discriminating mutations for shadows, reassignment, request binding, module, alias, optional call, readfile, fixed path and duplicate import. The imported callee is not bound by the lexical variable API: `Variable` represents declarators, loop and catch bindings, and named formals, not imported names. The source-declared import and whole-file exclusions are conservative attribution, not proof of lexical or runtime binding. A sink model would first need a supported import-binding identity and isolated tests for shadowing, same-name imports, reassignment, unsupported forms and malformed source, with exact call and argument identities and diagnostics on the pinned real file. Any subsequent flow query requires independently specified source-to-sink controls and the existing M4 and luci-ssl regression gates; #54 production promotion and consumer acceptance remain separate. Nonmatches cannot establish absence of a sink or safety. No sanitizer, authorization, reachability or exploitability conclusion follows.

## Focused smoke

`python3 ql/test/issue155-stat-observation/run-smoke.py --codeql /absolute/path/to/codeql --pack /absolute/path/to/extractor-pack --pack-sha256 DIGEST --pack-provenance /absolute/path/to/receipt --pack-provenance-sha256 DIGEST --pack-build-revision REVISION --producer-head REVISION --cache /absolute/path/to/cache --cache-sha256 DIGEST --output /absolute/path/to/fresh-output` is an opt-in test. It requires CodeQL 2.27.4, a prebuilt extractor pack for the intended revision and already resolved local QL dependencies; it does not install packs or download tools. The runner stages three separate datasets: the pinned real source, ten observation controls and five model controls; the two duplicate-import controls; and the malformed model control. The working-tree run described above used the current-base pack. The runner checks source bytes, routing identities, archived bytes, selected-file and error diagnostics, and exact row identities and multiplicity reconstructed from source-first spans and fresh raw AST entities. It checks the receiver read's formal target, the optional outer-member witnesses on both positive calls, and mutation controls for competing bindings/writes, request binding, import uniqueness, module, alias, optional calls, arity, spread and diagnostics. It does not establish runtime binding, sink or flow semantics. The detailed runner is not part of the default security suite; final-head and hosted validation remain separate.

`python3 ql/test/issue155-stat-observation/test-offline.py` tests parts of the checker and mutation construction without CodeQL; it is not an extraction test.

Before extraction, pass `--preflight-only` with a fresh output directory. This resolves each fixed and generated query and retains commands, streams, query hashes and a `preflight-complete.json` receipt. The extraction invocation uses a second fresh output directory and supplies that receipt through `--preflight-receipt`; it checks the query, complete query and library source trees, workspace files, effective library packages, CLI, pack build receipt and initial cache against the receipt before and during execution. These files are local execution evidence, not authenticated execution or a sandbox guarantee. Resolver and smoke inputs, commands and outputs still require independent review.

In its separate malformed dataset, the detailed runner expects one `parse_error` at line 3, columns 12–12 (inclusive), no success row and no model row. A prebuilt `ucode.so` parsed the pinned source with tree-sitter CLI 0.27.1, recovering the call and one `ERROR` at zero-based `[2,11]–[2,12]`; the shared extractor's location conversion yields the expected CodeQL coordinates. The parser binary's relationship to the recorded generated source has not been independently established. The subsequent working-tree extraction returned one error at the predicted location; final-head validation remains separate. The diagnostic-guard mutant must return the recovered call and exact path argument.

The arity, spread and missing-argument mutation queries are separate raw-predicate counterparts of the guards; they do not modify `Models.qll`. The current runner does not include family-widening or wrong-accessor mutations, so it does not establish their detection. Those remain test limitations until separately exercised.

The more detailed opt-in runner above remains a separate, retained-evidence workflow; neither gate adds a security query to the default suite.
