# Committed interchange snapshots

The five classified JSON arrays under `docs/` contain 19 committed typed
`handler_effect` and `taint_path` records. The four classified coverage JSON
objects are report-only summaries, not interchange records; they do not gain
`record_type` or `producer` merely because they are JSON. The filename and
coverage-field manifests in `tests/test_interchange.py` make additions or shape
changes explicit. `tests/fixtures/legacy-interchange-manifest.json` declares the
historical IDs, revisions, types, per-record statuses, resource identities,
unknowns and required references by array; `tests/fixtures/legacy-coverage-manifest.json`
records the four historical reports. These are preservation fixtures, not
oracles for new/live producer output. The test checks the exact classified
document set, IDs (including same-count substitutions), per-family revisions,
snapshot types, statuses and resource identities, required unknowns and report
contents. It also validates coverage profile, family revision, partial status, applicable entrypoint, string
arrays and nested call sites. Coverage is report-only and remains partial. There
is no imported-callee coverage report in this legacy bundle.

The bounded record checks require unique nonempty IDs, `producer: step3`,
`analysis_revision` matching the entire regular expression `step3:[^\s:]+`,
`handler_effect` or `taint_path` (not `rpc_surface` or `backend_method`), the
declared profile, SHA-256-shaped corpus revisions, and conditional assumptions
and unknowns arrays; every inconclusive row needs at least one non-whitespace
unknown, including rows outside the historical snapshots. Assessed rows require
an expectation and a grant reference;
declared aggregate effects must omit `session_class`. Required legacy evidence
references are checked, and every historical required `ql/` query path is checked
locally. The two M3 synthetic rows are legacy exceptions with no
invented evidence. Unresolved imported-callee and shellquote snapshots cannot
silently become `no_path` in this preservation test. A referenced query file is
not proof of query execution. These checks are not full JSON Schema conformance,
reference resolution, factual correctness, or scoped-analysis completeness.

These are committed snapshots, not output automatically regenerated by the QL
queries or by this test. Their corpus revision identifies the OpenWrt lockfile
hash used when they were prepared; this repository has no copy of that lockfile,
and the test checks format and consistency, not that the digest matches a live
sibling checkout. Revalidate against the matching OpenWrt `corpus/lock.json`
when transferring or refreshing evidence. Do not mint a new digest from this
repository's files.

A consumer joining a record to OpenWrt policy must require exact equality of
`corpus_revision` and `profile`, then the applicable entrypoint/ingress and
ubus object/method or CGI endpoint keys and referenced evidence IDs, as defined
in OpenWrt `docs/pack-contract.md`. `analysis_revision` is producer-local and
must not be equated across producers. These tests do not perform the join or
validate grants, sessions or lock correspondence. For declared aggregate
`handler_effect` records the proposed paired rule requires at least one primary
grant matching the assessment expectation; other identity-matching grants may be
supplementary, not support for that assessment. For `taint_path`, every cited
grant must match the expectation and caller; a grant-free unassessed path need not
invent either. Exact identity includes corpus, profile, ingress, entrypoint and
ingress-specific keys. An unassessed aggregate may cite grants without an
expectation; an unassessed taint path citing a grant still requires an
expectation. The producer checks these structural requirements but does not
perform the paired policy-context joins. The record-type pin prevents the
historical taint row from being
retagged as an aggregate to weaken its join; it is not an independent type
oracle for arbitrary new records. The committed `no_path` and `inconclusive`
statuses remain explicit scoped records; neither the tests nor an importer should
infer either status from an absent SARIF result.

`tests/fixtures/issue83-structural-v1.json` and
`tests/fixtures/issue83-structural-v2.json` are byte-pinned shared structural
subsets, run in the normal test gate against this producer's bounded record
checker. The consumer runs the same v1 (14 cases) and v2 (24 cases) fixtures;
v1 remains pinned for compatibility. These vectors cover structural rules only,
not semantic or provenance conformance. The producer
does not resolve grant IDs, compare caller or resource identity with grants, or
validate the schema and lockfile. The resource-identity pin covers ingress,
entrypoint, ubus object, method and CGI endpoint, including absence for synthetic
rows; it is a historical guard, not an identity oracle for new records. Only
required historical query references are resolved locally; arbitrary extra query
references and non-query references are not resolved here.

Historical unknowns are required as exact-string members, not an exact ordered
list: additional unknowns and reordering are permitted, but loss or substitution
is not. Coverage reports have an exact field set and exact scalar scope values,
including `partial` status. List order is immaterial. Every historical string,
including every unknown, and every complete `line`/`kind`/`command` call-site
object must remain present. Only `unknowns` may gain well-formed entries; all
other lists must retain the same length and historical members, including the
empty `trusted_summaries` list. This is the consumer's historical preservation
rule, not proof that the reported scope was executed or complete. Consumers must
not treat these summaries as a live-output scope oracle.

The fixed 19 records and four reports are historical guards, not live-output
cardinality or proof of scope completeness. A live handoff needs separate run
provenance, required artifacts and a separately pinned scope oracle; agreeing
with producer-advertised IDs alone only proves delivery matches the declaration.
In particular, this snapshot test does not exercise a fresh CSV through the
consumer adapter or validate both retained effect artifacts.

Run the offline check with:

```sh
python3 -m unittest discover -s tests -v
```

## Opt-in typed setBlockDetect source observation (v1)

The exporter is a non-writing, deliberately single-family interface; it does
not change the CSV query, historical snapshots or their validators. For a
source root containing only the pinned installed LuCI file, after running and
decoding the existing table and both diagnostic queries to CSV, invoke:

```sh
python3 -B tools/export_setblock_detect.py \
  --csv observation.csv --extracted extracted.csv --errors errors.csv \
  --source-root /absolute/source/root --lock /path/to/corpus/lock.json > typed.json
```

All five inputs are required. Inputs must be UTF-8; CSV uses standard quoting
and parsed rows, not a prescribed byte spelling. The table header and sole row
are exactly, in order:

```text
observation_kind,method,sink_kind,command,source_path,start_line,start_column,end_line,end_column
callback_body_call,setBlockDetect,system,/sbin/block detect > /etc/config/fstab,usr/share/rpcd/ucode/luci,532,21,532,68
```

The successfully-extracted diagnostic is exactly two rows: header `f,col1`,
then the absolute canonical resolved source-root joined with
`usr/share/rpcd/ucode/luci`, and an empty second column. The errors diagnostic
is exactly one header row `error,col1,col2` and no data rows. These shapes
match CodeQL 2.27.4 CSV decode, not arbitrary SARIF or a path substring search.
Additional successfully extracted files also fail this deliberately narrow
contract. Supply a source root corresponding to the paths in the diagnostic.
The source bytes must hash to
`6f9d972958d9cfb8a7ba421f38f0a5b03718ffeb0e30d460b64c9faf725fc54e`;
the lock must be strict JSON without duplicate keys or non-JSON constants and
`repos.luci.sha` must equal `b2e0be4b46ec0fd43394c081fa7c50657af14011`.
Other lock content is not independently validated. `corpus_revision` is
`sha256:` plus the SHA-256 of the **raw supplied lock bytes**, including
whitespace. Invalid, missing, extra, duplicate or unsupported inputs cause a
nonzero exit, a diagnostic on stderr and no JSON on stdout; they do not produce
an empty or safe result.

On success stdout is exactly one UTF-8 JSON array containing one record,
serialized with sorted keys, two-space indentation, ASCII escaping and a final
newline. `tests/fixtures/setblock-typed-v1.json` is the complete versioned
consumer-shareable field, type, string and list-order contract, with corpus
revision for the byte-identical `tests/fixtures/setblock-lock-v1.json`. Other
valid lock bytes change only `corpus_revision`. The record is a `handler_effect`
`fact`, producer `step3`, `analysis_revision` `step3:setblock-typed-v1`,
`assessment` `unassessed`. It uses the existing aggregate identity, source
location, three conditions, source/query references and conservative unknowns.
It has no session, expectation or grant reference: the consumer must validate
an independent family oracle and perform its own policy assessment. A query
reference identifies a query, not a claim that it was executed; source and
lock hashes or supplied diagnostics cannot authenticate execution or freshness.
The test fixtures exercise synthetic input, not an observed query run. Callback
registration, runtime execution, policy authorization, taint and broad coverage
are not established. There is no new typed coverage record; coverage remains
partial. The paired typed consumer and an observed fresh end-to-end run remain
separate work.
