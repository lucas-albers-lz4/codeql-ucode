# Committed interchange snapshots

The five classified JSON arrays under `docs/` contain 19 committed typed
`handler_effect` and `taint_path` records. The four classified coverage JSON
objects are report-only summaries, not interchange records; they do not gain
`record_type` or `producer` merely because they are JSON. The filename and
coverage-field manifests in `tests/test_interchange.py` make additions or shape
changes explicit. The offline standard-library test also checks unique nonempty
record IDs, `producer: step3`, producer-local `step3:*` analysis revisions,
profile, SHA-256-shaped corpus revisions, and the conditional assumptions and
unknowns arrays. It rejects `producer: step4`. It checks a bounded subset of
the contract, not full JSON Schema conformance or factual correctness.

These are committed snapshots, not output automatically regenerated by the QL
queries or by this test. Their corpus revision identifies the OpenWrt lockfile
hash used when they were prepared; this repository has no copy of that lockfile,
and the test checks format and consistency, not that the digest matches a live
sibling checkout. Revalidate against the matching OpenWrt `corpus/lock.json`
when transferring or refreshing evidence. Do not mint a new digest from this
repository's files.

A consumer joining a record to OpenWrt policy must require exact equality of
`corpus_revision` and `profile`, then the applicable entrypoint/ingress and
ubus object/method or CGI endpoint keys and referenced evidence IDs, as defined
in OpenWrt `docs/pack-contract.md`. `analysis_revision` is producer-local and
must not be equated across producers. These tests do not perform the join or
validate grants. The committed `no_path` and `inconclusive` statuses remain
explicit scoped records; neither the tests nor an importer should infer either
status from an absent SARIF result.

Run the offline check with:

```sh
python3 -m unittest discover -s tests -v
```
