# Bounded direct-copy receiver observation

`ql/src/m4/ReceiverDirectCopy.ql` reports an extracted source-level relation for one selected shape: a direct variable declarator initialized from a direct, source-declared `fs` `popen(...)` binding; one direct identifier copy of that variable; and a direct non-optional `read` or `close` member call whose receiver read is from that exact copy definition. The query joins source, copy read, copy write, and receiver read using AST, variable, and SSA-definition identity. It does not resolve the member call target.

The relation includes a call made before an alias reassignment. It excludes calls whose receiver read comes from the replacement write, and calls made after reassignment before the first use. It also excludes direct uses of the original binding, multi-step alias chains, computed properties, unrelated objects, and same-spelling lexical shadows. These cases are represented in `ql/test/receiver-provenance/direct-copy-controls.uc`; the separate `ReceiverDirectCopyCallInventory.ql` and `EXPECTED_CALLS` oracle require all 17 call sites (including computed-property and negative-control calls) to be extracted. The output oracle compares source declaration, initializer, copied declaration, receiver, and call entities with multiplicity.

Run `bash scripts/m4-receiver-direct-copy-smoke.sh` for a fresh isolated extraction, exact routing and successful-file checks, zero extraction-error check, nonvacuous call-site inventory, and exact three-row oracle. The `ci-ql-smoke.sh` glob discovers this script automatically and fails on its error status.

These rows are bounded evidence about extracted syntax and the current local SSA representation. They do not establish runtime targets, resource identity, successful `popen`, complete language semantics, safety, reachability, taint, or security coverage. Nonmatches are inconclusive. This experiment does not change the extractor/schema, `getIdentifier`, member-call dispatch, or production models, and does not satisfy the production hold in #48 or the Models gate in #50.
