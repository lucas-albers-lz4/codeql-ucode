# Bounded direct-copy receiver observation

`ql/src/m4/ReceiverDirectCopy.ql` reports an extracted source-level relation for one selected shape: a direct variable declarator initialized from a direct, source-declared `fs` `popen(...)` binding; one direct identifier copy of that variable; and a direct non-optional `read` or `close` member call whose receiver read may flow from that exact copy definition. The query joins the copy read to the exact initializer expression, and joins source, copy write, and receiver read using variable and SSA-definition identity. Each transfer uses a single `localFlowStep`; no transitive alias-chain closure is requested. It does not resolve the member call target.

The relation includes a call made before an unconditional alias reassignment and a positive `close` call. It excludes calls after an unconditional replacement write and calls where the source was overwritten before the copy. A conditional replacement produces a row after the merge because the original copy may reach the read along one path. Therefore, a row is may-reach evidence; it does not mean the receiver always has that origin. The controls also cover a multi-step alias chain, computed properties, unrelated objects, and a same-spelling lexical shadow. `ql/test/receiver-provenance/direct-copy-controls.uc`, `ReceiverDirectCopyCallInventory.ql`, and `EXPECTED_CALLS` require all 25 call sites (including these positive and negative cases) to be present. The output oracle compares source declaration, initializer, copied declaration, receiver, and call entities with multiplicity.

Run `bash scripts/m4-receiver-direct-copy-smoke.sh` for a fresh isolated extraction, exact routing and successful-file checks, zero extraction-error check, nonvacuous call-site inventory, and exact five-row may-reach oracle. The `ci-ql-smoke.sh` glob discovers this script automatically and fails on its error status.

These rows are bounded evidence about extracted syntax and the current local SSA representation. They do not establish runtime targets, resource identity, successful `popen`, complete language semantics, safety, reachability, taint, or security coverage. Nonmatches are inconclusive. This experiment does not change the extractor/schema, `getIdentifier`, member-call dispatch, or production models, and does not satisfy the production hold in #48 or the Models gate in #50.
