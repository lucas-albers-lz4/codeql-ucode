## Predeclared source-first expectation

Each case in `controls.uc` has one fs popen with a template. Expected inventory is exactly seven cases direct, fixed, unrelated, copy, overwrite, shadow, unknown, plus the real `getSwconfigFeatures` and `getSwconfigPortState` calls. The source for control dependency is the result of `source()`; the real-site source is the *result* of the syntactically named `shellquote` call, not `request.args`. Expected witnesses are exactly direct, copy, getSwconfigFeatures, getSwconfigPortState. Fixed has no interpolation; unrelated interpolates a different value; overwrite replaces the prior value before use; shadow reads the inner value; unknown interpolates the result of `unknown(source())`, for which propagation from the inner source to the outer result is not established. None of those five should be interpreted as a general proof about arbitrary code. Inventory includes all nine sinks and templates, so these negatives do not disappear at the sink/template gate.

The candidate query joins existing `DataFlow::localFlow(source, substitution)` to the direct AST fact that the same substitution expression is a direct part of the selected template. This final construction dependency is *introduced only by the experimental query*: no DataFlow node or edge was created or changed. It describes the substitution value as an input to construction, not value preservation, an ordinary DataFlow PathGraph path, runtime execution, executable resolution, shell quoting, or security. The baseline instead requires an actual template ExprNode reached by existing `localFlow`. It reports zero. The candidate reports four witnesses, with the full exact entity URIs, start/end lines and columns, and multiplicity in `Issue54DependencyProbe2.json`. At both real sites source and substitution are the same call expression, so the existing local flow is zero steps; the new observable is the construction input relation. It makes no assertion that the request argument affects the unknown call return, even though source nesting can be separately observed. Input-to-return behavior is deliberately unmodeled. The source-first expectation for direct interpolation uses documented compiler-source evaluation semantics in `docs/m4-template-string-call-arguments.md`; this experiment did not execute ucode or attest a runtime version.

The mutation query drops localFlow and requires only same-method nesting; it returns eight rows, introducing unrelated, overwrite, shadow, and unknown, with fixed still absent since it has no substitution. Thus the negative cases discriminate this loss of value identity; direct and copy remain positive. The mutation tests the significance of the value-flow gate, not every possible error. Full outputs, query sources, stderr, commands and location-bearing inventory are retained.

## Next boundary

A first-class DataFlow representation would need a separate design for template node identity, argument identity and transform edges, alongside exact alias/CFG regressions. Widening `TExpr` would change the established `Call.getArgument` and CFG contracts and is not automatically safe. Propagation through unknown `shellquote` still needs its own justified semantics; this experiment does not supply them. Any issue #51 promotion requires independent honesty audit and relevant exact-head gates. Production migration remains held under #50.

Issue #51’s usefulness gate is not met: this experiment adds a new test-only query observation, and does not demonstrate a changed result in an existing dependent query. Issue #54 remains gated on its own model, query, controls and consumer acceptance; this experiment does not promote a family.
